# DiamondScout AI — 라이트 스포츠 브로드캐스트 UI 리디자인 설계

## 배경 / 문제

2026-08-03에 "야간경기 스타디움"(다크 네이비+네온) 컨셉으로 위저드 UI를 개편했으나, 실제 라이브 화면을 확인한 결과 다음 문제가 발견됨:

- CTA 버튼 색이 통일되지 않음 (`다음`=초록, `⚾ 분석 실행`=청록, `🔄 다시 분석`=보라) — 주요 액션이 뭔지 시각적으로 구분되지 않음
- Gradio 기본 컴포넌트(PDF 다운로드 버튼, 파일 드롭존)가 커스텀 다크 테마 카드 사이에서 스타일링되지 않은 채 그대로 노출되어 이질감
- 결과 화면(코칭 보드) 섹션 간 여백이 붕 떠 보임 — 세로 나열 구조라 내용 밀도가 낮아 보임
- 데스크톱에서 콘텐츠 폭이 좁은 중앙 칼럼(~900px)에 고정되어 있어 넓은 화면에서 공간 활용이 안 됨

사용자 피드백: "반응형 + 현대적 + 모던 + 심플 + 야구 느낌 팍하게"

## 목표

1. 색·타이포·컴포넌트 스타일을 하나의 일관된 시스템으로 재정의한다 (톤: 밝고 스포츠 방송 그래픽 같은 느낌)
2. CTA 버튼 색상 규칙을 통일한다 (주요/보조 2종만 사용)
3. 결과 화면을 벤토 그리드로 재구성해 밀도와 여백 문제를 해결한다
4. 데스크톱 넓은 화면을 실제로 활용하는 반응형 레이아웃을 적용한다
5. Gradio 기본 컴포넌트(다운로드 버튼, 드롭존)를 새 비주얼 시스템에 맞게 재스타일링한다

## 범위

- 대상: `app.py`의 `CUSTOM_CSS`, `gr.Blocks(theme=...)`, 투수 모드/타자 모드 위저드 레이아웃, 결과 화면(코칭 보드/STRIKE ZONE BOARD/전략 리포트) 레이아웃, 타석 시뮬레이터·Instant Scout Q&A 탭의 색상/폰트
- 비대상: `services/*`, `models/*` 백엔드 로직, 4단계 위저드 스텝 순서·구성(매치업→상황판→베이스&스코어→작전지시)은 [2026-08-03 설계](2026-08-03-game-ui-overhaul-design.md)에서 확정된 대로 유지, `gr.State` 기반 스텝 전환 메커니즘 유지

## 비주얼 시스템 — 라이트 스포츠 브로드캐스트

### 색상

| 역할 | 색상 | 용도 |
|---|---|---|
| 배경 | `#f4f2ec` (크림 오프화이트) | 전체 배경 |
| 카드 배경 | `#ffffff` | 스텝 카드, 벤토 카드 |
| 카드 테두리 | `#e6e1d3` | 카드 보더 |
| 주 텍스트/헤더 | `#14203c` (네이비) | 브랜드, 제목, 라벨 |
| 주요 액션 | `#c8102e` (레드) | Primary 버튼, 활성 탭, 진행 표시 완료 스텝 |
| 안전/추천 | `#1f8a4c` (그린) | 위험도 낮음 등 긍정 신호 |
| 주의 | 앰버 계열 | 위험도 중간 |
| 위험 | 레드 계열 (`#c8102e` 톤) | 위험도 높음 |
| 통계 숫자 | 모노스페이스, 레드 | 구종 확률 등 강조 수치 |

### 버튼 규칙 (기존 3색 혼재 → 2종 통일)

- **Primary**: 레드 배경 + 흰 텍스트 — `다음 ➡`, `⚾ 분석 실행` 등 진행/실행 액션
- **Ghost/Outline**: 투명 배경 + 네이비 테두리/텍스트 — `⬅ 이전`, `🔄 다시 분석` 등 보조 액션
- 결과 상태 색(그린/앰버/레드)은 버튼에 쓰지 않고 위험도 표시 전용으로만 사용

### 타이포그래피

- 브랜드/헤더: 기존 콘덴스드 스포츠 폰트(Teko) 유지 — 라이트 배경에서도 스포츠 방송 그래픽 느낌 유지 가능
- 통계 숫자(구종 확률 등): 모노스페이스(Share Tech Mono 등) — 스코어보드 LED 느낌 유지, 숫자에만 한정 적용

### 진행 표시 (위저드 스텝 인디케이터)

- 기존: 회색 박스 4개 나열 + 점선 구분선
- 변경: 번호 원(●) + 연결선 트랙. 완료 스텝은 레드 채움+체크, 현재 스텝은 네이비 채움+포커스링, 남은 스텝은 아웃라인만
- 데스크톱은 원 아래 텍스트 라벨(매치업/상황판/...) 표시, 모바일은 원만 표시(공간 절약)

## 결과 화면 — 벤토 그리드

- 기존: 코칭 보드 섹션들이 세로로 나열되며 헤더-내용 사이 여백이 붕 뜸
- 변경: `추천 구종`, `상대 타자 약점`, `위험도 카드`를 정사각형에 가까운 벤토 카드로, `STRIKE ZONE BOARD`는 와이드 카드(2~4칸)로 배치
- 모바일: 2열 그리드 / 데스크톱: 4열 그리드 (와이드 카드는 2칸 차지)
- `전략 리포트`(PDF 다운로드) 섹션은 카드 형태로 감싸고, Gradio 기본 버튼·드롭존 스타일을 카드 톤(흰 배경, 네이비 테두리, 레드 강조 아이콘)에 맞춰 CSS 오버라이드

## 반응형 레이아웃

| 브레이크포인트 | 구조 |
|---|---|
| 모바일 (`<640px`) | 1열 스택. 진행 표시는 원만(라벨 숨김). 위저드 카드 풀폭. 결과 카드 2열 |
| 태블릿 (`640–1279px`) | 모바일과 동일한 1열 스택이나 중앙 칼럼 폭 확대. 결과 카드 2열 유지 |
| 데스크톱 (`≥1280px`) | 2단 레이아웃: 좌측(약 60%) 위저드 스텝 카드, 우측(약 40%) "현재 매치업" 요약 패널(네이비 배경, 지금까지 입력한 투수/타자/카운트/이닝을 스텝 전환 중에도 상시 표시). 결과 카드 4열 |

- "현재 매치업" 패널은 신규 컴포넌트이지만 기존 `gr.State`에 담긴 값을 읽어 표시만 하는 순수 프레젠테이션 레이어 — 백엔드 로직·상태 관리 방식 변경 없음
- 데스크톱 전용 컴포넌트이므로 CSS `@media` 쿼리로 노출 여부만 제어 (Gradio 컴포넌트 자체는 항상 렌더링, `visible=`을 추가로 쓰지 않고 CSS 반응형 처리)

## 적용 대상 탭

- **투수 모드 / 타자 모드**: 위 위저드 + 결과 화면 레이아웃 전체 적용
- **타석 시뮬레이터 / Instant Scout Q&A**: 이미 단일 동작 흐름이라 구조 변경 없음. 색상 시스템(크림/네이비/레드)과 폰트만 통일

## 리스크 / 결정 사항

- Google Fonts `@import`(Teko, Share Tech Mono)는 외부 네트워크 요청 필요 — 기존과 동일한 리스크, 로컬망 차단 시 시스템 폰트로 폴백되며 레이아웃은 깨지지 않음
- Gradio 기본 컴포넌트(파일 다운로드 버튼, 드롭존) 재스타일링은 Gradio 버전 업데이트 시 내부 클래스명이 바뀌면 깨질 수 있음 — CSS 선택자에 주석으로 Gradio 버전 명시
- "현재 매치업" 패널은 데스크톱에서만 보이므로, 모바일 사용자는 매치업 정보를 다시 보려면 STEP 1로 돌아가야 함 (기존과 동일한 제약, 악화 없음)
- 이번 개편도 UI 레이어 한정. `services/*` 계산 로직, RAG/LLM 흐름, 위저드 스텝 순서는 그대로.
