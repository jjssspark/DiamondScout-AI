# DiamondScout AI — 야간경기 위저드 UI 개편 설계

## 배경 / 문제

- 현재 UI는 `.gradio-container`에 다크 테마 CSS를 씌우고 있지만, Gradio 6 기본 테마가 라이트라 일부 내부 컴포넌트(카운트 스코어보드 등)에 CSS가 적용되지 않아 라이트/다크가 뒤섞여 보이는 버그가 있다.
- 투수 모드 / 타자 모드 모두 모든 입력 필드(투수/타자 선택, 카운트, 이닝, 주자, 스코어, 전략 코멘트)가 한 화면에 나열되어 있어 "게임처럼 하나씩 진행되는" 느낌이 없다.

## 목표

1. 라이트/다크 뒤섞임 버그를 근본적으로 고친다.
2. 투수 모드 / 타자 모드를 "야간경기 위저드" — 한 번에 한 스텝만 보여주고 완료하면 다음 스텝으로 넘어가는 게임형 플로우로 개편한다.
3. 전체 비주얼을 "야간경기 스타디움" 컨셉으로 대폭 강화한다.

## 범위

- 대상: `app.py`의 투수 모드 / 타자 모드 탭 UI 레이어 + `CUSTOM_CSS`
- 비대상: `services/*`, `models/*` 등 백엔드 로직 (분석 결과 계산 방식은 변경 없음)
- 타석 시뮬레이터 / Instant Scout Q&A 탭: 이미 한 번에 한 동작씩 진행되는 구조라 위저드화하지 않음. 색상·폰트만 새 비주얼 시스템에 맞춰 통일.

## 다크 테마 버그 수정

- `gr.Blocks(theme=..., css=CUSTOM_CSS)`에 `gr.themes.Base()` 기반 커스텀 다크 테마를 명시적으로 지정해, Gradio 6 기본 라이트 프리셋이 어디에도 새어나오지 않게 한다.
- 기존 `.ds-*` 클래스 선택자는 유지하되, 테마 레벨에서 다크 컬러가 기본값이 되므로 CSS는 포인트 컬러/텍스처 보강 역할만 하도록 정리한다.

## 위저드 플로우

투수 모드 / 타자 모드 동일한 4스텝 패턴:

1. **매치업** — 내 투수 / 상대 타자 선택
2. **상황판** — 볼-스트라이크-아웃 + 이닝/이닝초말
3. **베이스 & 스코어** — 1·2·3루 다이아몬드 토글 + 스코어
4. **작전 지시** — 전략 코멘트 입력 + `⚾ 분석 실행` 버튼

### 상태 관리

- `gr.State(step_index)`로 현재 스텝(1~4)을 추적한다.
- 4개 스텝 카드는 모두 정적으로 렌더링해두고 `visible=` 토글로 하나만 보이게 전환한다 (Gradio에서 컴포넌트를 동적으로 새로 만들지 않는, 검증된 안전한 패턴).
- 상단 고정 바에 완료된 스텝은 작은 요약 칩으로 표시하고, 칩 클릭 시 해당 스텝으로 즉시 이동할 수 있다.
- 각 스텝 카드에는 `다음 ➡` 버튼(마지막 스텝은 `⚾ 분석 실행`)과, 2번째 스텝부터는 `⬅ 이전` 버튼을 둔다.

### 결과 화면 전환

- 4스텝 제출(분석 실행) 시 위저드 카드 영역은 숨기고, 기존 코칭 보드 / STRIKE ZONE BOARD / Instant Scout Q&A 영역을 새 비주얼로 보여준다.
- 결과 화면 상단에 `🔄 다시 분석` 버튼을 두어 누르면 위저드를 1스텝으로 리셋한다 (입력값은 유지, 화면만 전환 — 처음부터 다시 입력하지 않아도 되도록 직전 값을 유지한 채 스텝 카드로 돌아감).

## 비주얼 시스템 — 야간경기 스타디움

- 배경: 기존보다 더 진한 네이비~블랙 그라디언트 + 조명 vignette, 필드 그린 라인 포인트
- 폰트: 헤더 — 콘덴스드 스포츠 폰트(Teko 계열, Google Fonts `@import`), 숫자(카운트/퍼센트) — 모노스페이스 LED 스타일
- 색 체계: 네온 그린(안전/추천) · 앰버(주의) · 레드(위험) — 기존 위험도 카드 색을 전체 UI로 확장
- 카드 테두리에 야구공 실밥 라인 텍스처(SVG/CSS), 버튼 hover 시 살짝 튀어오르는 트랜지션

## 리스크 / 결정 사항

- Google Fonts `@import`는 외부 네트워크 요청이 필요하다. 로컬망 차단 환경에서는 폰트가 시스템 기본으로 폴백되지만 레이아웃은 깨지지 않는다.
- 위저드 상태 전환은 Gradio `visible=` 토글 기반이라 컴포넌트 개수 자체는 늘어나지 않음 — 성능 영향 없음.
- 이번 개편은 UI 레이어 한정. `services/*` 계산 로직, RAG/LLM 흐름은 그대로다.
